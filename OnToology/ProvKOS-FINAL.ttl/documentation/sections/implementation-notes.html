ProvKOS & PROV-O Alignment

This ontology defines several sub-properties of PROV-O properties to reflect the operational reality of classification systems. The following table summarizes the mapping:

ProvKOS PropertySuper-propertyDomainDefinition
pk:wasDeprecatedByprov:wasInvalidatedBypk:ClassNumberThe existing class number is deprecated, becoming "unassigned."
pk:wasAuthorizedByprov:wasGeneratedBypk:ClassNumberAn "unassigned" number is being used to represent a concept.
pk:wasWarrantedByprov:wasInfluencedByprov:ActivityThe activity was justified by external evidence (Warrant).

The domain restriction on pk:wasDeprecatedBy and pk:wasAuthorizedBy reflects the operational reality of classification systems, where class numbers persist as reusable containers: a deprecated number becomes "unassigned" and may later be re-authorized for a new concept. For labels (skosxl:Label), the standard PROV-O properties apply directly: prov:wasGeneratedBy for newly created labels, and prov:wasInvalidatedBy for labels that are retired. Thesauri and other KOS that operate solely with concepts and labels—without persistent class numbers—can use the standard PROV-O properties throughout, without requiring the ProvKOS sub-properties.
